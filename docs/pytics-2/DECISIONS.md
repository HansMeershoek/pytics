## DEC-001

| Title | Pytics 2.0 is a clean redesign |
| Status | Accepted |
| Decision | 2.0 is a clean redesign of the product, not a blind incremental refactor of the 1.1.5 architecture. The 1.1.5 codebase is a functional and historical reference. Algorithms, tests, behavior, and ideas may be reused only deliberately. Nothing is inherited automatically. |

## DEC-002

| | |
| --- | --- |
| Title | Product identity |
| Status | Accepted |
| Decision | Pytics is an analytical microscope for datasets, for professional data scientists and data analysts. Its purpose is to understand a dataset, relationships, data-quality characteristics, a supplied target, the comparison of two datasets, and changes and drift. The goal is understanding, not optimizing predictive performance. |
| Rationale | Stated as the core concept and primary purpose in the bootstrap briefing. |
| Implications | `REQ-P-01`, `REQ-P-02`. Features that exist to raise a model's score are outside the product. |

## DEC-007

| | |
| --- | --- |
| Title | Semantic-first inference |
| Status | Accepted |
| Decision | Physical dtype is not sufficient. Infer semantic meaning. The minimum concepts are Numeric, Categorical, Boolean/Binary, Text/String, Datetime, Timedelta, Identifier, Constant, and Empty. Subtypes may exist where useful. Inference retains type, confidence, evidence or reasoning, and relevant metadata. Inference must not mutate the original DataFrame. Inference should be intelligent and transparent. |
| Rationale | Stated semantic-first principle, including the minimum concept list and the non-mutation rule. |
| Implications | `REQ-S-01` through `REQ-S-09`. Boolean conservatism is [DEC-014](#dec-014) via section D, refined by [DEC-047](#dec-047). |
| Later update | [DEC-041](#dec-041) through [DEC-054](#dec-054) refine inference, confidence, overrides, coercion, Empty/Constant, identifiers, numeric and string meaning, datetime and timedelta, ordinal policy, eligibility, and sampling. Subtype taxonomy remains [OPEN-014](#open-questions). The ordinal storage question remains [OPEN-016](#open-questions). |
| Later update | [DEC-064](#dec-064) through [DEC-076](#dec-076) record the semantic-foundation consolidation. They refine the inference pipeline, evidence roles, v0.1 scoring scope, material alternatives, Identifier and string meanings, binary representation pressure, overrides, and evidence reuse. They do not close the open questions named in those decisions. |
| Later update | [DEC-077](#dec-077) specifies the stored counts and derived facts of the universal column-evidence family. It does not add a semantic type. |

## DEC-041

| | |
| --- | --- |
| Title | Semantic inference system v0.1 |
| Status | Accepted |
| Decision | Physical dtype, observed characteristics, and semantic interpretation are distinct. Physical pandas dtype is evidence, not the final analytical meaning, and the original physical dtype stays inspectable. Inference is evidence-driven, through conceptual stages of physical classification, basic evidence, pattern and structural evidence, candidate semantic types, conflict resolution, and semantic interpretation. Those stages are not a frozen function decomposition. An interpretation must be able to retain semantic type, subtype where relevant, confidence, supporting evidence, alternative interpretations where relevant, and source. Sources include inferred, directly supported by physical dtype, and explicitly configured by the user. Exact object names are not accepted. |

## DEC-055

| | |
| --- | --- |
| Title | Relationship result and pair-type direction |
| Status | Accepted as direction. Not a closed method catalog. |
| Decision | A relationship separates description, effect, uncertainty, frequentist inference, Bayesian inference where appropriate, diagnostics, and method metadata. A relationship is not reduced to a p-value. Exact Python objects are not accepted. Accepted pair-type direction, still subject to validation during implementation design: numeric with numeric uses Spearman as a monotonic or rank perspective and Pearson as a linear perspective where applicable, plus uncertainty where methodologically appropriate, sample size, and missing-pair information. Pearson and Spearman are not treated as the same phenomenon. Deep analysis may add Kendall, bootstrap confidence intervals, permutation or resampling inference, and further robust or nonlinear diagnostics where justified. Numeric with binary includes per-group sample sizes, group descriptive statistics, observed group differences, an appropriate standardized effect, uncertainty, and frequentist evidence. Welch-family inference is currently preferred over blindly assuming equal variances. Robust or rank-based evidence may complement it. Numeric with categorical, for more than two groups, prioritizes group descriptive statistics, an overall relationship or effect, and an appropriate omnibus test. Every pairwise comparison is not dumped automatically. Post-hoc pairwise analysis belongs primarily in deeper analysis and uses appropriate multiple-testing control. Binary with binary is not reduced to chi-square significance. Relevant concepts include contingency counts, observed proportions, absolute proportion or risk difference, relative measures where meaningful, association strength, uncertainty, and frequentist evidence. This pair is a strong candidate for lightweight Bayesian analysis. Categorical with categorical uses contingency information, observed proportions, Cramér's V or another appropriate association-strength measure, and appropriate inferential evidence. Sparse or small tables may require exact or resampling alternatives. Extreme high-cardinality pairs are protected from meaningless or computationally explosive analysis. Identifiers are excluded by default. Datetime is not converted to integer timestamps and passed through ordinary correlation. Datetime with numeric focuses on meaningful temporal structure when justified, such as trend, change over time, temporal association, and periodic or seasonal structure where justified. Datetime with categorical may examine changes in category distribution or temporal patterns. A datetime column by itself does not establish a time-series context. Ordinal relationships apply only where [DEC-052](#dec-052) accepts ordinal semantics. |
| Rationale | Effect, uncertainty, and method are the interpretation. Pair type changes which of those quantities are meaningful. |
| Implications | `REQ-K-01`, `REQ-K-04`. This does not retire `REQ-K-03`. Exact formulas, selection rules, default binary-binary measures, datetime methods, and unlisted pair types remain [OPEN-006](#open-questions). [DEC-031](#dec-031) still keeps trend, seasonality, and autocorrelation off the default pass for every datetime column. Their scope remains [OPEN-020](#open-questions). |

| Title | Multiple testing, no stars, assumptions as diagnostics |
| Status | Accepted as direction |
| Decision | Where multiple-testing correction applies, raw and adjusted p-values are distinct. False-discovery-rate control is the preferred default direction for broad relationship screening. | Title | The target diagnostic model is one untuned linear probe per task, scored on a held-out split against a naive baseline |
| Status | Accepted |
| Decision | TSK-034 adds the first diagnostic predictive model for an explicitly selected target. Its question is whether a single simple, untuned model recovers held-out predictive signal for the target from the other columns, compared with a naive baseline on the same rows, and which input columns that held-out signal is sensitive to. It is not a search for the best model. There is no hyperparameter tuning, no grid, random, or Bayesian search, no model comparison, no leaderboard, no model selection, no ensembling, no calibration or threshold choice, no SHAP, no class weights, no deployment, no export, no prediction API, and no retained estimator. Nothing in it is a causal statement. **Ownership.** `pytics.analysis.target_diagnostic` holds the frozen result and its consistency rules and does not import scikit-learn. `pytics.analysis.target_diagnostic_fit` is the only module that imports scikit-learn. `analyze_target_diagnostic(frame, columns, target, *, seed=0)` is its entry point. `DatasetAnalysis.target_diagnostic` is a sibling of `target_analysis`, present exactly when a target was requested. `TargetAnalysis` is unchanged: [DEC-103](#dec-103) keeps it a projection that reads no source values, and fitting reads the frame. An unavailable model is a status on the diagnostic record and cannot change the target projection, the relationship records, or their Benjamini–Hochberg values. `TargetSummary.diagnostic` is a copied diagnostic. `DatasetAnalysis` checks the attachment without refitting: link by target position, task, target-side population and class counts against the retained descriptive facts, and every predictor's identity, selected type, and resolution status. Nothing is exported from top-level `pytics`, and `profile` is unchanged. **Task.** The semantic target type is not the predictive task, and the semantic type is never changed to obtain one. A Boolean target is binary classification. A Categorical target is binary classification with two observed classes and multiclass classification with three or more. A Numeric target is regression, including Numeric `{0, 1}`, which is not re-read as Boolean. Datetime, Timedelta, Text, Empty, Constant, Identifier, and unresolved targets have no task. The class count is the observed class count already retained by Boolean or Categorical descriptive analysis. **Statuses.** `AVAILABLE`, `TARGET_TYPE_UNSUPPORTED`, `INSUFFICIENT_TARGET_CLASSES` (fewer than two observed classes, so no task), `TOO_MANY_TARGET_CLASSES` (more than 100), `INSUFFICIENT_TARGET_POPULATION` (fewer than 20 modeling rows), `INSUFFICIENT_TARGET_VARIATION` (a regression target whose finite minimum equals its maximum), `VALIDATION_SPLIT_IMPOSSIBLE` (a class with fewer than two modeling rows), `NO_ELIGIBLE_PREDICTORS`, and `NUMERICAL_FAILURE` (a prediction or validation score that is not a finite float64). They are checked in that order. The target-side statuses are decided from retained facts before the frame is read for fitting. 20 rows, two rows per class, and 100 classes are feasibility and computational bounds. They are not reliability thresholds and not a high-cardinality definition. No exception is converted into a status. Inconsistent arguments raise, and an internal invariant raises. **Population.** The diagnostic records total rows, the target's own missing rows from target analysis, non-missing Numeric target values that are not finite, and the modeling rows that remain. Those three reconcile with the total. Training and validation counts exist after the split and reconcile with the modeling rows. Classification also records each observed class with its training and validation counts. TSK-032 target population facts are not altered. **Predictors.** Every other column, in physical order, is recorded once predictor screening is reached. The target is never a predictor. Numeric, Boolean, and Categorical are candidates. Identifier, Empty, Constant, and unresolved columns are excluded under those names. Datetime, Timedelta, and Text are `UNSUPPORTED_TYPE`. There is no timestamp feature engineering and no text model. Identifiers cannot be configured back in, because no configuration exists. A candidate of the target's own semantic type that equals the target on every modeling row is `IDENTICAL_TO_TARGET`. Numeric equality is on the float64 image. Categorical equality is on the category values, not on codes or vocabularies. A missing predictor value on any modeling row means the column is not a copy. That is a duplicate guard. It is not leakage detection: a relabeled copy, a partial copy, a post-outcome column, and an association are not detected or labeled. The remaining candidates are decided from the training rows only. A column with no varying training image is `NO_TRAINING_VARIATION`. A Numeric column with one finite value still varies when some training rows are missing, because its missing indicator differs. A Categorical column with more than 1,000 training levels, including a missing level, is `TOO_MANY_LEVELS`, and its level count is retained. Categories are not truncated. A Numeric column whose training mean or population standard deviation is not a finite float64 is `SCALE_NOT_FINITE`. **Validation.** One holdout with a validation fraction of 0.25, seed 0. Cross-validation was rejected for this slice. It fits the model several times, splits the meaning of "the model" and of its importance across folds, and multiplies runtime by the fold count, and the stability it buys is not needed to answer a coarse diagnostic question. Classification uses a stratified holdout implemented in Pytics: in class order, each class contributes `ceil(0.25 * n_class)` validation rows, at least one and at most `n_class - 1`, drawn by `numpy.random.default_rng(seed)`. Every class is therefore present in both parts, so every metric is defined and the classifier sees every class. Regression draws `ceil(0.25 * n)` validation rows from a random permutation from the same generator. The split depends only on target values and the seed. No row index, mask, or generator is retained. **Preprocessing.** One scikit-learn `Pipeline` of a `ColumnTransformer` and the estimator is fitted on the training rows only. A Numeric column, with missing and non-finite values treated as missing, uses `SimpleImputer(strategy="median", add_indicator=True)` then `StandardScaler()`. A Boolean or Categorical column is encoded from integer codes, `-1` for missing, by `OneHotEncoder(handle_unknown="ignore")`. Missing is its own level when training rows contain it. A level absent from the training rows encodes as all zeros. Codes avoid stringifying category values and avoid ordering mixed-type levels. One-hot of codes is not an ordinal encoding. There is no target encoding. The design matrix is sparse whenever a one-hot block exists. The source frame is not modified. This preprocessing is internal to the probe and is not a recommendation. **Estimators.** Classification is `sklearn.linear_model.LogisticRegression(C=1.0, solver="lbfgs", max_iter=1000)`. Regression is `sklearn.linear_model.Ridge(alpha=1.0, solver="auto")`. Every other argument is the library default. `penalty` is not passed, because the tested scikit-learn 1.9.1 reports it as deprecated. The default is L2. Both are convex and deterministic, cheap, and have one conventional regularization default on standardized inputs. Tree ensembles, gradient boosting, and a single decision tree were not chosen: they are randomized or need more fixed settings, and they would be the first step toward a model comparison. The consequence is stated: a linear probe can miss non-linear and interaction signal, so a small improvement over baseline is not evidence that no signal exists. Logistic-regression solver convergence is retained. A `ConvergenceWarning` is suppressed because it is retained. **Baselines.** `DummyClassifier(strategy="prior")` predicts the training class proportions. `DummyRegressor(strategy="mean")` predicts the training mean. Each baseline is fitted on the same training rows and scored on the same validation rows. MAE is compared with the mean predictor, not the median predictor. **Metrics.** Classification: ROC AUC for binary and the unweighted macro mean of one-versus-rest areas for multiclass, both by the Mann–Whitney rank formula with tied scores sharing average ranks; balanced accuracy as the mean per-class recall of the most probable class, with a probability tie going to the first class in class order; and log loss in natural logs with probabilities clipped to `[1e-15, 1]` and not renormalized. Regression: R² against the validation mean, not clamped and allowed to be negative; MAE; and RMSE. Each metric stores the model value and the baseline value. `improvement` is derived, positive when the model is better under that metric's direction. It is not a predictability score, and there is no highly, moderately, or weakly predictable label. R² is undefined when the validation target is constant. Then the model and baseline R² are absent and no replacement value is stored. No metric uncertainty interval is computed. **Permutation importance.** The change in held-out performance when one original input column is permuted on the validation rows while every other validation input is unchanged, with 5 repeats from the seed. Classification scores the negative log loss. Regression scores R². A one-hot column and a Numeric column with its missing indicator move as one original input. There is no dummy-level importance. Each repeat stores the validation score minus the permuted score. For log loss that is permuted loss minus original loss. The mean and the population standard deviation across repeats are derived. Negative values are kept. Importance is the sensitivity of held-out performance to perturbing that input under this model. It is not causality, an effect, significance, or a relationship strength, and correlated inputs can share or hide it. Importance follows physical column order. It is not a ranking and it does not reorder target relationship links. When R² is undefined, importance is absent. **Reproducibility.** The design retains the validation strategy, fraction, seed, estimator and baseline identities, the passed estimator parameters, the importance metric, the repeat count, and the scikit-learn version. Results are reproducible for the same data, Pytics version, library versions, and seed. **Retention.** No estimator, pipeline, transformer, DataFrame, Series, ndarray, sparse matrix, callable, random generator, row index, or mask is retained. Every number is a Python float or int. **Dependency.** scikit-learn becomes a declared runtime dependency, `scikit-learn>=1.3`, by the TSK-034 brief. No other machine-learning dependency was added. The floor is audited against the APIs called, all present in 1.3, the version `requirements-pinned.txt` already named. The later update below lists the APIs after the TSK-034b hardening. Only 1.9.1 was tested, with SciPy 1.18.1, NumPy 2.5.3, pandas 3.0.6, and Python 3.14.8. The floor is not a lock and not a pin. The module-level import adds about 0.6 s to importing the analysis package, which already takes about 4.5 s. **Performance.** On this machine, NumPy generator seed 32, a 20,000-row frame with 8 Numeric, 4 Boolean, and 4 Categorical columns and 16 included predictors: base `analyze_dataframe` about 0.85–0.95 s, of which relationships about 0.75–0.83 s. [DEC-074](#dec-074) does not accept `{0.0, 1.0}`. Numeric-structure evidence can count that pair as two finite integer-like values ([DEC-079](#dec-079)). That observation does not accept the pair as binary evidence. Physical numeric `{0, 1}` and `{0.0, 1.0}` may support a Numeric candidate ([DEC-083](#dec-083)). That support is not binary evidence. The variables summary gives both pairs Numeric detail ([DEC-090](#dec-090)). Boolean descriptive analysis does not count either pair ([DEC-092](#dec-092)). Numeric × Boolean relationships give both pairs the Numeric role ([DEC-100](#dec-100)). That is not binary evidence. Do not implement either pair as binary evidence while this question is open.

### OPEN-047

The inferred result represents post-resolution abstention and ambiguity. `InferredSemanticResult` carries the observed physical dtype and the `SemanticResolution` ([DEC-086](#dec-086)). `INSUFFICIENT_EVIDENCE` means no structural reading was supplied and no candidate is supported. `AMBIGUOUS` means more than one candidate is supported and no reviewed rule selects between them. Neither status is a `SemanticType`. On the inferred result, neither status has a `SemanticInterpretation` or a selected type. That is a valid inferred state. It is not an error, and it is not `None` from `interpret_series_precedence`. A structural `RESOLVED` result keeps the existing interpretation. A candidate-derived `RESOLVED` result keeps the selected semantic type and does not yet have a `SemanticInterpretation`, because no High, Medium, or Low confidence is assigned ([DEC-085](#dec-085), [DEC-086](#dec-086)). What remains open is candidate-derived confidence, material alternatives once one reading is selected while another stays plausible, and how a public result should represent these states. Do not treat candidate counts as confidence. Do not turn ambiguity into a low-confidence selected reading. TSK-016 now produces this inferred result from one Series ([DEC-087](#dec-087)). TSK-017 keeps that same inferred result on each column analysis ([DEC-088](#dec-088)). Neither orchestration assigns candidate-derived confidence. TSK-018 counts a resolved selected type, including a candidate-derived selection that has no `SemanticInterpretation` ([DEC-089](#dec-089)). That count does not assign confidence. TSK-019 represents insufficient evidence and ambiguity as variable states with no selected type and no specialized detail ([DEC-090](#dec-090)). It does not assign candidate-derived confidence, and it does not turn ambiguity into a selected reading.

### OPEN-048

Is an evidence-strength enum ever needed? [DEC-066](#dec-066) keeps evidence role, evidence strength, and resolution confidence distinct, and does not introduce an evidence-strength enum for Candidate Resolution v0.1. User-facing confidence remains High, Medium, and Low.

### OPEN-049

What is the exact behavior when a user override meets an Empty or Constant column? [DEC-075](#dec-075) accepts override direction and does not freeze this case. Exact error and warning behavior for other overrides is also unset. Result and configuration shapes remain [OPEN-004](#open-questions) and [OPEN-009](#open-questions).
